# Two-lesson trial of `nestjs-learn` 2.0.0 (2026-11-07)

A scripted trial on a throwaway app, run before merging the 2.0.0 skill. Lesson 1 scaffolds the app. Lesson 2 adds one endpoint with a database. The learner is a script, not a person: it reads one step at a time with `learn.mjs step`, types exactly the code the guide shows, runs the commands it shows, and then runs the step's check. This proves the guides are complete and correct as written. It doesn't measure how easy they are to learn from.

## Setup
- Owner repository: `notes-api`, empty apart from `docs/plan.md` (health, create note, read note) and `learn/learn.config.json`.
- Tools: Windows 11, Git Bash, Node 24.22.1, pnpm 11.13.0, Docker 29.6.2, Nest 12, Vitest, Prisma 7.10.1, Postgres 18.
- Each lesson was built and proved first in its own worktree, outside the repository. Lesson 2's proof used a throwaway `docker run --rm` Postgres on a random local port. Its `.env` was written fresh from `.env.example`, and the effective database host was printed and confirmed before any test.
- `learn.mjs scan` picked each lesson: `no_nest_app` for lesson 1, and `missing: POST /api/v1/notes` for lesson 2.

## What the trial found and fixed
| Found | Fix |
|---|---|
| Prisma 7's generated client imports itself in loops, so `arch` failed with 3 `no-circular` errors in code nobody wrote | New `generatedDirs` setting in `nestjs-modular-monolith` 1.1.0: imports inside generated code aren't followed, imports into it are still checked. Self-test cases and a unit test prove both sides |
| Copying the lesson's unit test at the start made `add-module` refuse, because the module folder already existed | Tests for a folder the lesson creates are copied when giving the first step after it exists |
| `nest new .` refuses a folder with a `README.md` | Move it aside and back; noted in `write.md` |
| The scaffold's `.gitignore` missed `*.tsbuildinfo` | Added to the scaffold notes in `write.md` |
| pnpm 11 skips Prisma's install scripts unless they're listed in `allowBuilds` | The guide writes `pnpm-workspace.yaml` before adding Prisma; noted in `write.md` |
| Prisma 7 no longer generates the client during `migrate dev` | Explicit `prisma generate` in the guide and `write.md` |
| Whole-project `tsc` fails mid-lesson, because copied tests import files not typed yet | `done.md` falls back to the step's own check |
| `learn.mjs cleanup` failed on Windows with "Filename too long" inside pnpm's `node_modules`, leaving files behind | Removal runs with `core.longPaths=true`; rerun on a fresh pnpm worktree removed it and its empty parent |
| A lesson 1 quiz answer claimed `\|\|` turns `PORT=0` into 3000. Env values are text, so `"0"` is truthy | Answer and guide corrected; a planted mistake now proves the empty-`PORT=` case |

## Limits
- The learner is a script that follows the guide exactly. A person makes other mistakes, and the coaching replies (`done`, `check`) weren't scored.
- One machine, Windows only. Linux and macOS runs wait for CI (#29).
- No remote, so no PR: merge detection in `cleanup` was tested with stubbed `gh` output, and both lessons were removed with `--abandoned`.
- Evidence (learner logs and planted-mistake tables) lived in the session's temporary folder and isn't kept.
